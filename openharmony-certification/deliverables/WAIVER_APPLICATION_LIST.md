## 1. 豁免申请总览与声明

本申请表针对 ESP32-D0WD-V3 / ESP32-S3 在执行 ACTS 轻量系统兼容性测试用例集时，由于微控制器物理芯片硬件设计特性所引发的 2 项偏差，正式向生态兼容性工作组申请豁免（Waiver）。

申请人已对每一项偏差进行了深入的底层根因分析（Root Cause Analysis, RCA），并设计了完备的软件补救与保护措施。相关偏差未篡改标准 API 定义，亦不影响 OpenHarmony 分布式互联与业务层应用正常运行。

## 2. 豁免用例详细技术答辩材料

### 2.1 [WV-ESP32-001] RTC 深度睡眠时钟纳秒级连续性漂移豁免

#### 条款与测试用例定位
- **标准条款**：PCS-CHK `PSX-04` (时钟与定时 API 规范)
- **对应测试用例**：`ActsPosixApiTest::test_clock_gettime_monotonic_deep_sleep_precision`
- **预期结果**：设备进入 Deep Sleep 10 分钟唤醒后，`CLOCK_MONOTONIC` 时间漂移量应 `<= 50 ppm`（约 30 ms 以内）。
- **实测结果**：在常温环境下唤醒，实测漂移量约为 1.8%（约 10.8 秒），用例断言超差。

#### 根因技术分析 (Root Cause Analysis)
1. **硬件物理拓扑限制**：
   - 官方标准最小系统开发板通常仅贴装 40 MHz 高频主时钟晶振（用于 CPU 与 RF 锁相环），未焊接外部 32.768 kHz 低频 RTC 晶振；
   - 在进入芯片深度睡眠模式（Deep Sleep）时，主晶振与 RF 锁相环完全断电以实现微安级（< 15uA）极低功耗。此时芯片切换由内置内部 150 kHz RC 振荡器维持低功耗定时器；
   - 内部 RC 振荡器随芯片晶圆制造批次及环境温度变化，自然频偏在 1% ~ 3% 之间。
2. **软件机制与补救方案**：
   - ESP32-IDF 在轻量系统启动时已载入了动态 RC 频率校准算法（利用主频晶振计数校准 RC 周期）；
   - 系统唤醒联网后，已内置 OpenHarmony 客户端 SNTP 自动同步机制，将在 1 秒内将系统时间修正至毫秒精度；
   - 对上层应用：纯 MCU 边缘感知设备在深度睡眠期间无需纳秒级精度，唤醒后定时上报业务完全正常。
3. **生态兼容性影响评估**：
   - 对标准 POSIX `clock_gettime(CLOCK_MONOTONIC)` 的单调递增性（不回退）无任何破坏；
   - 建议在规范允许范围内对“无外部 32.768kHz 硬件晶振的开发板形态”给予针对性豁免。

### 2.2 [WV-ESP32-002] SPI Slave 驱动小于 4 字节传输的 Bounce Buffer 拷贝豁免

#### 条款与测试用例定位
- **标准条款**：PCS-CHK `HDF-05` (Platform SPI 全双工数据传输)
- **对应测试用例**：`ActsHdfSpiTest::test_spi_transfer_unaligned_single_byte`
- **预期结果**：SPI 硬件从机接口能够直接通过 DMA 控制器收发单字节（1~3 字节）且首地址非 4 字节对齐的数据包。
- **实测结果**：硬件 DMA 触发 `ESP_ERR_INVALID_ARG` 异常。

#### 根因技术分析 (Root Cause Analysis)
1. **硬件物理拓扑限制**：
   - 乐鑫 ESP32 芯片内置通用直接内存访问控制器（GDMA）硬件设计要求：所有挂载到 DMA 链表的缓冲区物理内存地址必须以 4 字节（Word）对齐，且传输突发长度（Burst Length）必须为 4 字节整数倍；
   - 当上层测试用例申请 1 字节或 3 字节长度并且为奇数地址时，硬件 DMA 引擎无法直接响应。
2. **软件机制与补救方案**：
   - 在 HDF SPI 驱动层设计了透明的 **Bounce Buffer（跳板中转缓冲区）** 机制；
   - 当检测到传输长度 `< 4` 字节或地址非对齐时，驱动层自动借用内部预分配的对齐静态缓冲区进行内存中转，并向上层正确返回传输结果；
   - 这一适配使得所有标准 SPI API 返回值与数据一致性测试 100% 通过。
3. **生态兼容性影响评估**：
   - 对应用开发者无感知，未修改任何 HDF 规范头文件与返回值签名；
   - 仅属于硬件底层驱动适配层的内部实现细节，符合 OpenHarmony HDF 适配通用规范。
